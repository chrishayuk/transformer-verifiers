## 5. LARQL versus reference: disagreements and potential disagreements

None of the following changes the computation **for this config.json and this container**, except item 5.6, which is unverified. Each is a place where a different upstream config, or a different reading, would make the two sides compute different things.

1. **Sliding-window resolution (the main one).**
   - Reference (`cq3:87, :91-97`): if `use_sliding_window` is true and `sliding_window` is non-null and `layer_types` is not declared, layers with `i >= max_window_layers` slide. If `layer_types` is declared, it is used verbatim and `max_window_layers` is ignored.
   - LARQL (SPEC §17.5): layers with `L >= max_window_layers` never slide; layers below it slide only if `layer_types[L]` says so; with no `layer_types`, nothing slides.
   - Example: `use_sliding_window: true`, `sliding_window: 4096`, `max_window_layers: 21`, 28 layers, no `layer_types`. Reference: layers 21-27 slide. LARQL: no layer slides.
   - Example: `layer_types` marking layer 25 `"sliding_attention"` with `max_window_layers: 21`. Reference slides layer 25; LARQL does not.
   - Defaults also differ: `sliding_window` absent and `use_sliding_window: true` gives the reference its class default 4096 (`cq3:78`); LARQL rule 1 treats an absent window as not sliding.
   - A declared `layer_types` with `use_sliding_window: false`: the reference keeps the `"sliding_attention"` labels but with `sliding_window = None`, while LARQL rule 1 gives full. Edge case, not reached.
   - The comparator detects all of these only if its expected per-layer span comes from the reference's read-back `layer_types`/`sliding_window`, not from SPEC §17.5.
2. **`tie_word_embeddings` absent.** The LARQL writer stores `head_reuses_embedding: true` (§17.6). The reference class default is `False` (`cq3:74`), so it would use a separate `lm_head`, and leave it randomly initialised if the checkpoint has none. Not reached: upstream declares `true`.
3. **RoPE variants.**
   - `partial_rotary_factor`: LARQL would emit `"partial_rope"` (§17.5). Qwen3's `compute_default_rope_parameters` (`mq3:124-133`) never reads it and rotates the whole head.

## 6. Runtime defaults the harness must pin explicitly (D2: "nothing is filled in silently")

Each of these is something the reference uses that config.json does not state, or that the library would fill in differently from what the comparison assumes.

1. **Attention implementation.** `config._attn_implementation` is `None` from config.json (`cu:285`), so `get_correct_attn_implementation` picks **`"sdpa"`** (`mu:1889`), falling back silently to eager if SDPA cannot dispatch (`mu:1916-1923`). The mask path also depends on it (`T/masking_utils.py:946`). Pin `attn_implementation="eager"`, the only path whose scale, mask and softmax arithmetic are visible in source (`mq3:196-218`), and assert `model.config._attn_implementation == "eager"` after construction.
2. **Compute dtype.** `from_pretrained` defaults to `dtype="auto"` (`mu:3950-3951`), which resolves to config.json's `torch_dtype` = **bfloat16** (`cu:241-249`). Pin `float32` for ref32 and `float64` for ref64 explicitly; record that `config.dtype` reads back as bfloat16 and is overridden. Also pin `torch.get_default_dtype()` = float32.
3. **RoPE table construction.** `rope_type = "default"` selects `compute_default_rope_parameters` (`mq3:96-100`), which builds `inv_freq` in f32 (`mq3:131`) at construction as a non-persistent buffer (`mq3:102-103`), and `forward` forces f32 (`mq3:142`). A later `.to(float64)` only casts the f32 values. The AMB-013 patch must recompute them in f64; freeze and record the patch sha256. Assert `rope_type == "default"`, `attention_scaling == 1.0`, `inv_freq` length 64.
4. **Read-back normalisation.** Freeze, with the checker, the mapping from 5.5.0's effective config to config.json's keys: `rope_scaling: null` ⇔ `rope_parameters == {"rope_type": "default", "rope_theta": 1000000}` (no other keys); `rope_theta` ⇔ `rope_parameters["rope_theta"]` (int vs JSON integer, exact); `sliding_window: null` ⇔ read-back `None`; `layer_types` must be 28 × `"full_attention"`; `dtype` excluded and recorded separately. This is a harness setting, but because D2 says "a difference makes the run invalid", the owner should confirm the mapping (protocol decision) before E2.
5. **Expected per-layer span.** Derived from read-back `config.layer_types` and `config.sliding_window` (and `model.model.has_sliding_layers == False`, `mq3:370`), never from SPEC §17.5's writer rules (§5.1).
6. **Cache.** `use_cache` with no cache passed creates `DynamicCache(config=...)` (`mq3:394-395`), whose layer structure follows `layer_types`/`sliding_window` (`T/cache_utils.py:1204-1226`). Pin the cache class (DynamicCache, no static, quantised or offloaded cache) and pass it explicitly.
7. **Position ids.** Defaulted to `arange + past_seen_tokens` (`mq3:397-400`). Pass them explicitly for the teacher-forced, one-token-at-a-time schedule.
8. **Tied weights.** Construction ties `lm_head.weight` to `embed_tokens.weight` (`mu:3077`). `from_pretrained` re-ties symmetrically and **silently unties** with only a warning if both tensors are present and differ (`mu:2533-2546`). If E2 loads the checker's decoded weights through `load_state_dict` with both keys, the shared parameter takes whichever is written last. Pin: load the decoded embedding once; assert `lm_head.weight.data_ptr() == model.embed_tokens.weight.data_ptr()` after loading; separately assert that the decoded output head equals the decoded embedding.
9. **Hub kernels.** `RMSNorm`, `SiLU` and `rotary_pos_emb` carry `use_kernel_*_from_hub` decorators (`mq3:49, :158, :221`; `T/activations.py:93`). The `kernels` package is not installed, so they are no-op stubs (`T/integrations/hub_kernels.py:247-262`); `use_kernels` defaults to False (`mu:3936`), and `USE_HUB_KERNELS` defaults to `"YES"` (`hub_kernels.py:59`), which would matter if `kernels` were installed. Pin: assert `kernels` is not importable and pass `use_kernels=False`; record the environment.
10. **Mode and dropout.** `model.eval()`; `attention_dropout` is 0.0 from config.json and only used when training (`mq3:283`). Assert `model.training is False`.
11. **Torch numerics (arithmetic, record with E2):** float32 matmul precision `"highest"`, thread count, deterministic algorithms, device CPU.
